# CIFAR-10 Image Classification & Real-Time Prediction Web App

An end-to-end computer vision project: data preprocessing, CNN model
training (from-scratch + transfer learning), evaluation, Grad-CAM
explainability, and two deployment options (Streamlit UI + Flask REST API,
containerized with Docker).

Built to satisfy the full project brief: data exploration → preprocessing →
model development → optimization → deployment → documentation, plus both
bonus features (Grad-CAM explainability, Flask+Docker deployment).

## Project Structure

```
image-classification-app/
├── src/                        # Core pipeline (importable, reusable)
│   ├── config.py                # Central config: paths, classes, hyperparameters
│   ├── data_preprocessing.py    # Load, explore, augment, split CIFAR-10
│   ├── model.py                 # Custom CNN + MobileNetV2 transfer-learning models
│   ├── train.py                 # Training loop (early stopping, LR scheduling)
│   ├── evaluate.py              # Accuracy/precision/recall/confusion matrix
│   └── gradcam.py               # Grad-CAM explainability
├── app/
│   └── streamlit_app.py         # Interactive web app (upload → predict → explain)
├── api/
│   ├── flask_app.py             # REST API (/health, /predict)

├── notebooks/
│   └── 01_Image_Classification.ipynb   # Exploratory / documented walkthrough
├── models/                      # Saved model + metadata (generated by train.py)
├── outputs/                     # Training plots, confusion matrix, reports (generated)
├── data/                        # Local dataset cache (generated)
├── requirements.txt
└── .gitignore
```

## Setup

```bash
python -m venv venv
venv\Scripts\activate        # Windows: venv\\Scripts\\activate
pip install -r requirements.txt
```

## 1. Train a model

```bash
cd src
python train.py --model_type mobilenet --epochs 30       # transfer learning (recommended)
python train.py --model_type custom_cnn --epochs 40       # CNN built from scratch
python train.py --model_type mobilenet --fine_tune_at 100 # fine-tune the backbone
```

This downloads CIFAR-10 automatically on first run (via
`tf.keras.datasets.cifar10`), trains with early stopping + dropout +
LR-reduction-on-plateau, and saves:

- `models/cifar10_model.keras` — the trained model
- `models/model_metadata.json` — which architecture was trained (read
  automatically by the apps/evaluation script)
- `outputs/training_history.png` — accuracy/loss curves

> **No internet / offline environment?** `train.py` automatically falls back
> to a small synthetic, class-structured dataset (and MobileNetV2 falls back
> to random-initialized weights) so the entire pipeline stays runnable for
> smoke-testing, e.g. `python train.py --demo --epochs 3`.

## 2. Evaluate

```bash
python evaluate.py
```

Prints accuracy/precision/recall/F1 per class and saves:

- `outputs/classification_report.txt`
- `outputs/confusion_matrix.png`

## 3. Run the Streamlit app

```bash
streamlit run app/streamlit_app.py
```

Three modes, switchable in the sidebar:

- **Classification (CIFAR-10)** — one label per image, confidence bar chart, Grad-CAM heatmap.
- **Object Detection - Fixed 80 classes (YOLOv8)** — finds and localizes **multiple objects**
  in a single image (person, car, dog, bicycle, laptop, chair, bottle, and 80 COCO classes
  total), each with its own bounding box, label, and confidence score. Pretrained,
  no setup needed.
- **Object Detection - Open Vocabulary (YOLO-World)** — not limited to a fixed list. Type
  any object names, comma-separated ("coffee mug, solar panel, bicycle helmet", or
  anything else) and it looks for exactly those, zero-shot. This is how you get past a
  small fixed category list without needing to train a custom model — the underlying
  model matches image regions to text descriptions, so its *effective* vocabulary is
  unbounded. No real-time detector runs 10,000+ classes at once with good accuracy in a
  single pass; this "ask for what you want" pattern is how production systems with huge
  concept spaces actually work. First use downloads extra CLIP weights (~370MB) and
  needs internet access.

## 4. Run the Flask API (bonus)

```bash
python api/flask_app.py
```

- `GET /health` → `{"status": "ok", "model_type": "mobilenet"}`
- `POST /predict` (multipart form, field `file`) → single-label classification + Grad-CAM:
  ```json
  {
    "predicted_class": "dog",
    "confidence": 0.93,
    "probabilities": { "airplane": 0.01, "...": "..." },
    "gradcam_overlay_base64_png": "iVBORw0KG..."
  }
  ```
- `POST /detect` (multipart form, field `file`, optional field `conf` default `0.25`) →
  fixed 80-class (COCO) multi-object detection with bounding boxes:
  ```json
  {
    "num_objects": 3,
    "detections": [
      {"class_name": "person", "confidence": 0.87, "box": [48.6, 398.6, 245.3, 902.7]},
      {"class_name": "bus", "confidence": 0.87, "box": [22.9, 231.3, 805.0, 756.8]}
    ],
    "annotated_image_base64_png": "iVBORw0KG..."
  }
  ```
- `POST /detect_custom` (multipart form, field `file`, optional field `classes` -
  comma-separated text labels, optional field `conf` default `0.10`) → open-vocabulary
  detection for whatever objects you specify:
  ```json
  {
    "queried_classes": ["coffee mug", "solar panel", "bicycle helmet"],
    "num_objects": 1,
    "detections": [
      {"class_name": "coffee mug", "confidence": 0.42, "box": [110.2, 88.5, 210.7, 190.1]}
    ],
    "annotated_image_base64_png": "iVBORw0KG..."
  }
  ```

Examples:
```bash
curl -X POST -F "file=@my_image.jpg" http://localhost:5000/predict
curl -X POST -F "file=@my_image.jpg" -F "conf=0.3" http://localhost:5000/detect
curl -X POST -F "file=@my_image.jpg" -F "classes=coffee mug, solar panel, bicycle helmet" http://localhost:5000/detect_custom
```

## 5. Run with Docker (bonus)

```bash
docker build -t cifar10-api -f api/Dockerfile .
docker run -p 5000:5000 cifar10-api
```

(Train a model first so `models/` has something to copy into the image.)

> **RAM note:** the Flask API loads both TensorFlow (classification) and
> PyTorch/YOLO (object detection) in the same process. On machines with
> limited RAM (~4GB), running both together can be memory-heavy. If you hit
> crashes, either run only the endpoint you need, or split `/predict` and
> `/detect` into two separate Flask processes/ports.

## Model Details

| Aspect | Custom CNN | MobileNetV2 Transfer Learning |
|---|---|---|
| Params | ~150K | ~2.4M (mostly frozen) |
| Training speed | Faster from scratch | Faster convergence (pretrained) |
| Typical use | Baseline / lightweight | Best accuracy, recommended default |

Both share the same input pipeline (96×96×3, normalized to `[0, 1]`),
loss (sparse categorical cross-entropy), optimizer (Adam), and are
selectable via `--model_type` on `train.py` or the `MODEL_TYPE` env var.

## Explainability (Grad-CAM)

`src/gradcam.py` implements Grad-CAM against the last convolutional block
of either architecture, producing a heatmap overlay showing which pixels
most influenced the predicted class — surfaced in both the Streamlit app
and the Flask API response.

## Notes on Dataset Access

CIFAR-10 downloads from `https://www.cs.toronto.edu/~kriz/cifar-10-python.tar.gz`
via Keras. In network-restricted environments (e.g. corporate proxies,
sandboxed CI), this can fail — the pipeline detects this and transparently
switches to a synthetic fallback dataset so every script still runs
end-to-end. On your own machine with normal internet access, the real
CIFAR-10 dataset (60,000 32×32 color images, 10 classes) is used
automatically.

## Version Control

This project is structured to drop directly into a Git repository:
`git init && git add . && git commit -m "Initial commit"`, then push to
GitHub. `.gitignore` excludes generated models/outputs/dataset caches by
default — pin a specific model in your repo by removing the relevant
line if you want to version it too.
